# API reference

Geodata MCP exposes two HTTP surfaces on a single origin (fronted by Caddy, see
`deploy/Caddyfile`):

| Surface | Path prefix | Protocol | Purpose |
|---------|-------------|----------|---------|
| **Viewer & Data API** | everything except the two below | plain REST | map views, styles, GeoJSON, vector tiles, WMS proxy, workspace manager |
| **MCP control plane** | `/mcp` | streamable HTTP (JSON-RPC) | the LLM tool interface |
| OAuth 2 endpoints | `/oauth/*`, `/.well-known/oauth-*` | OAuth 2 | authorization for `/mcp` |

The **Viewer & Data API** is documented by the running service at `/openapi.json`.
Route definitions, parameter descriptions and response metadata are the single
source for both this schema and the interactive documentation.

## Viewing the specification

### Interactive docs (FastAPI)

The viewer is a FastAPI app, so the schema and interactive explorers are served
live:

| URL | What it is |
|-----|------------|
| `http://localhost:8080/docs` | Swagger UI — try endpoints in the browser |
| `http://localhost:8080/redoc` | ReDoc — a readable, printable rendering |
| `http://localhost:8080/openapi.json` | FastAPI's auto-generated OpenAPI JSON |

(In local development the viewer container also answers directly on port `8001`;
`8080` is the Caddy front proxy used everywhere else.)

`GET /openapi.json` is generated by FastAPI from the route definitions at request
time, including descriptions, examples, capability checks and manager-cookie
authentication. Static files and the mounted metrics service are not API routes
and are omitted from the generated schema.

### Regenerating the JSON for CI

Export the schema for a release or client generator:

```sh
.venv/bin/python scripts/dump_openapi.py           # writes build/openapi.json
.venv/bin/python scripts/dump_openapi.py --check    # compare that export with the routes
# --output PATH selects a different artifact location
```

The script imports the same `main:app` that uvicorn runs and calls
`app.openapi()`; it performs no database or network access. Run it with the
viewer's dependencies available (`services/viewer/requirements.txt`). CI tests
the API contract and publishes the generated JSON as an artifact; generated
exports are not maintained in Git.

## Endpoint quick reference

All map/data endpoints are protected by **capability URLs**: a valid, unguessable
`view_id` is required and the requested layer must belong to that view (otherwise
`403`). No API key is sent by the map client.

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/healthz` | liveness probe |
| GET | `/v/{view_id}` | interactive map page (`?renderer=maplibre\|origo`) |
| GET | `/v/{view_id}/style.json` | MapLibre GL style (ETag conditional GET) |
| GET | `/v/{view_id}/origo.json` | Origo/OpenLayers configuration |
| GET | `/data/{layer}.geojson` | layer as GeoJSON (`view`, `crs`, `limit`) |
| GET | `/tiles/{layer}/{z}/{x}/{y}.mvt` | Mapbox Vector Tile (`view`) |
| GET | `/wmsref/{dataset_id}` | server-side WMS GetMap proxy (`view` + WMS KVP) |
| GET/POST | `/login`, `/logout` | workspace-manager sign in / out |
| GET | `/dashboard`, `/workspaces/{workspace_id}` | owned workspace overview and audit |
| GET | `/admin`, `/admin/audit`, `/admin/services` | administrator dashboards, audit and service status |
| POST | `/admin/services/action` | allowlisted service maintenance (admin + CSRF) |
| GET | `/workspaces` | workspace manager UI (session cookie) |
| POST | `/workspaces/action` | activate / rename / delete a workspace (CSRF) |
| GET | `/static/{path}` | bundled static assets |

### Authentication model

- **Map & data endpoints** — capability URLs only (see above); no credential
  header.
- **Workspace manager** (`/workspaces`) — a signed, HttpOnly session cookie
  (`gdw_auth`) issued by `POST /login` against the API key. It stores only the
  key id, never the key.
- **MCP control plane** (`/mcp`) — requires `Authorization: Bearer <api key>` or an OAuth 2 token (authorization code + PKCE; see
  `services/mcp/oauth.py`, discovery at `/.well-known/oauth-authorization-server`).

## The MCP tool interface (`/mcp`)

The control plane is a FastMCP streamable-HTTP server. It never sits in the data
path: tools write to PostGIS and return capability URLs; map clients then read
from the Viewer & Data API above. Every request must carry a bearer API key or OAuth token.

Add it to Claude:

```sh
claude mcp add --transport http geodata http://localhost:8080/mcp \
  --header "Authorization: Bearer $KEY"
```

The server exposes eight tools:

| Tool | What it does |
|------|--------------|
| `workspace` | list / create / switch / rename / delete the key's durable workspaces; optional `workspace_id` selects a workspace per call; otherwise the active one is used |
| `search` | hybrid trigram + embedding search over the catalog and document chunks; `id=` returns full schema + provenance |
| `load` | register sources (WFS/WMS/WMTS/OGC-API/STAC/file/PDF/text/inline), harvest capabilities, and ingest datasets into `ref`/workspace via a job queue; `op='embed'` refreshes embeddings |
| `query` | read-only SQL as `agent_ro` (PostGIS + pgvector, 15 s timeout, 1000-row cap); every call is logged with a `query_id` and its referenced tables |
| `layer` | the only write path: CTAS into the selected workspace, per-row updates, and style/notes; every op appends to the append-only `app.provenance` ledger |
| `map` | upsert a renderer-agnostic map view and return a capability URL rendered by MapLibre or Origo; open pages pick up changes within ~5 s via ETag polling |
| `analyze` | registry of long-running analysis processors (`list`/`describe`/`run`/`status`/`cancel`); results land as workspace layers (orthophoto change detection supports `params.backend="sam3"` or `"gemma"`) |
| `export` | GPKG/GeoJSON/CSV/Parquet via ogr2ogr to a presigned URL, with a citation sidecar; `export(job_id=...)` retrieves existing output without creating another job |

See [`../README.md`](../README.md) for the architecture, and [`../CONTRACTS.md`](../CONTRACTS.md) for the binding
implementation spec.
